4) Код:
```python
first = "python"
second = "py" + "thon"

print(first == second)
print(first is second)
```
Вывод: `True True`

Объяснение: 

`first == second` истина, потому что значения одинаковые

`first is second` тоже истинно в CPython. Выражение "py" + "thon" состоит из двух
литералов, поэтому компилятор вычисляет его ещё до запуска программы (constant folding) и
подставляет готовую константу "python". Строка "python" похожа на идентификатор, поэтому CPython интернирует её, то есть
хранит один общий объект. Оба имени получают ссылку на этот объект.

5) Правило для `==` и `is` - `==` проверяет равны ли значения объектов, подходит для чисел, строк, коллекций и объектов
классов, `is` проверяет идентичны ли объекты, т.е являются 
ли они одним объектом, подходит для `None`, `True`, `False`, для проверки, что две переменные ссылаются на один и тот же 
изменяемый объект в ячейке памяти.

### Контрольные вопросы: ###

2) `type()` возвращает тип, класс объекта, `id()` возвращает адрес объекта в памяти.
3) `==` используется для чисел и строк, потому что для них важно именно равенство значений, а не идентичность объектов.
`None` является синглтоном: во всей программе существует ровно один объект None, так что проверка идентичности точна и однозначна.

### Эксперимент C
````python
import math
result = 0.1 + 0.2
print(result)
print(result == 0.3)
print(result - 0.3)
print(math.isclose(result, 0.3))
````
Числа с плавающей точкой в большинстве современных языков (включая Python) хранятся в соответствии со стандартом IEEE 754
(как правило, двойная точность — 64 бита). 

Округление из-за ограниченной разрядности: Память компьютера ограничена. Бесконечный хвост обрезается и округляется до 
ближайшего представимого двоичного числа. Из-за этого `0.1` и `0.2` сохраняются в памяти с микроскопической
погрешностью.

Накопление погрешности: При сложении двух приближенных чисел погрешности суммируются. Получившаяся сумма оказывается равной примерно:`0.300000000000000044408920985`
В то же время само число `0.3` округляется до:`0.299999999999999988897769753` Поскольку их двоичные представления не совпадают на
последних битах, прямое сравнение `result == 0.3` возвращает `False`, а разность показывает эту самую погрешность порядка `5.55 \times 10^{-17}`.

Правило: числа типа `float` с плавающей точкой нельзя сравнивать с помощью `==` из-за погрешности. Нужно использовать `math.isclose(a, b)`
